SECURITY ARCHITECTURE
================================================================================

PATTERN: Every operation follows this flow:
  1. HTTP Request → Controller method
  2. Controller calls: toolkit.check_access('action_name', context, {})
  3. Check triggers auth function: auth.action_name()
  4. Auth function calls: _sysadmin_only() check
  5. If not sysadmin: return {'success': False} → controller aborts with 403
  6. If sysadmin: action executes → DB operation → response JSON

SECURITY MEASURES:
  - Sysadmin-only enforcement (all 19 actions)
  - Password verification for critical ops (reset_password, purge)
  - Self-protection (cannot delete/demote yourself)
  - System integrity (cannot remove last sysadmin, uses row lock)
  - Soft vs hard delete (delete = reversible, purge = permanent)
  - Input validation (password length, required fields)

  → toolkit.check_access() → auth check
  → toolkit.get_action('admin_user_reset_password')()
  → actions.admin_user_reset_password()
    - Get current sysadmin context
    - Verify sysadmin_password via user_obj.validate_password()
    - Set target_user.password = new_password
    - Session.commit()
  → Response JSON: {success: true, user_name: "...", message: "..."}

================================================================================
STORAGE PATTERNS
================================================================================

FEATURED DATASETS:
  - Stored as: Tags on CKAN packages
  - Tag name: "FeaturedDataset"
  - Query: package_search with facet filter fq='tags:FeaturedDataset'
  - Max results: 100 (hard-coded in action)
  - Retrieval order: Solr default (usually by score)

FEATURED PUBLICATIONS:
  - Stored as: Rows in featured_publication table
  - Table created: On first use via init_featured_publications_db()
  - Primary key: UUID
  - Retrieval order: display_order ASC, then created_at DESC
  - Queries: FeaturedPublication.get_all(), FeaturedPublication.get(id)

USER MANAGEMENT:
  - Stored as: Rows in CKAN core user table
  - Query: Direct SQLAlchemy on model.User
  - Filters: Name, email, fullname (case-insensitive ILIKE), state, sysadmin
  - Orders: name, name_desc, created, created_asc, email
  - Pagination: Configurable limit (max 100), offset-based
  - Related data: Organizations (via user.get_groups), Datasets (COUNT query)

================================================================================
AUTHENTICATION & AUTHORIZATION
================================================================================

AUTHENTICATION: Uses CKAN's built-in flask session & user context
  - c.user: Username (string)
  - c.userobj: User object from database
  - Available in templates and controllers

AUTHORIZATION: Two-layer check
  Layer 1 - Controller:
    try:
      toolkit.check_access('action_name', context, {})
    except toolkit.NotAuthorized:
      return base.abort(403, 'Not authorized')

  Layer 2 - Action:
    toolkit.check_access('action_name', context, data_dict)
    (raises NotAuthorized if check fails)

  Auth Function (auth.py):
    def action_name(context, data_dict):
      user_obj = context.get('auth_user_obj')
      if user_obj and user_obj.sysadmin:
        return {'success': True}
      return {'success': False}

ALL ADMIN ACTIONS: Sysadmin-only (17 total actions)

EXTENSION POINTS
================================================================================

To add a new admin module, follow this pattern:

1. DATABASE LAYER (model.py):
   - Define DomainObject class extending model.DomainObject
   - Implement __init__, @classmethod methods (get, get_all, etc)
   - Define SQLAlchemy table schema
   - Create init_*_db() function to ensure table exists

2. ROUTING LAYER (plugin.py:get_blueprint()):
   - Add blueprint.add_url_rule() for each endpoint
   - Point to controller methods

3. CONTROLLER LAYER (controller.py):
   - Add static methods to MyLogica class
   - Each method checks access first
   - Calls appropriate action
   - Returns rendered template or JSON

4. ACTION LAYER (actions.py):
   - Define action functions for each operation
   - Start with toolkit.check_access()
   - Implement business logic
   - Return dict or raise exceptions

5. AUTH LAYER (auth.py):
   - Define auth function for each action
   - Can be _sysadmin_only or more complex logic
   - Return {'success': bool} or {'success': bool, 'msg': error}

6. TEMPLATE LAYER (templates/admin/*.html):
   - Extend page.html
   - Add breadcrumb, header, content
   - Add JavaScript for AJAX and interactivity

7. REGISTRATION (plugin.py):
   - Register actions: get_actions() dict
   - Register auth: get_auth_functions() dict

ERROR HANDLING PATTERNS
================================================================================

In controllers:
  try:
    toolkit.check_access(...)
  except toolkit.NotAuthorized:
    return base.abort(403, _('Not authorized'))

  try:
    result = toolkit.get_action('...')()
  except toolkit.ObjectNotFound:
    return jsonify({...}), 404
  except toolkit.ValidationError as e:
    return jsonify({'error': e.error_dict}), 400
  except Exception as e:
    log.error(f'Error: {e}')
    return jsonify({'error': str(e)}), 500

In actions:
  toolkit.check_access('...', context, data_dict)  # Raises NotAuthorized
  
  required_field = toolkit.get_or_bust(data_dict, 'field')  # Raises ObjectNotFound
  
  if validation_fails:
    raise toolkit.ValidationError({'field': ['error message']})
  
  obj = model.get(id)
  if not obj:
    raise toolkit.ObjectNotFound('Not found')
